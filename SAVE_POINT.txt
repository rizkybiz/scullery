7. RESUMING ON ANOTHER MACHINE (READ THIS)
======================================================================
!! TERRAFORM STATE IS LOCAL AND GIT-IGNORED (infra/terraform/terraform.tfstate, plus
!! terraform.tfvars with project_id). A fresh clone has NO state: running `terraform apply`
!! there would try to create everything again and fail or duplicate. Copy these files from the
!! old machine (they contain no passwords you cannot rotate, but treat them as private):
!!    infra/terraform/terraform.tfstate
!!    infra/terraform/terraform.tfvars
!! or do not run Terraform on the new machine until state is moved to a GCS bucket.

Steps:
  git clone git@github.com:rizkybiz/scullery.git && cd scullery
  Tools: Node (version in apps/web/.nvmrc), Go, Docker, Terraform, gcloud, gh, vercel, gitleaks.
  cd apps/web && npm ci
  gcloud auth login && gcloud auth application-default login
  vercel login && vercel link   (RUN FROM THE REPO ROOT: the project's Root Directory is
                                  apps/web, so `vercel deploy` must also run from the root)
  .vercelignore at the root keeps the CLI upload under 100 MB.
  Local sign-in: apps/web/.env.local is git-ignored and does not travel. Recreate:
    read -rs PW && printf '%s' "$PW" | node apps/web/scripts/hash-password.ts
  Local dev OIDC token (12 h): `vercel env pull <file> --environment development`
  Local Docker stack for the API: services/api (see its README); local DB is separate from
  staging and production.
Checks: npm run typecheck / lint / format:check / build (npx next typegen first if types fail).
Go: services/api: make verify. Terraform: cd infra/terraform; terraform plan.
Do not stop processes with pkill -f / pgrep -f "next-server".

Things that live only on the old machine: Claude Code memory notes (~/.claude/projects/...),
the git-ignored files above, and the untracked tfplan files. The originals of the app are in
